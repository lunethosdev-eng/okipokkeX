Modelo de seguridad

Los paquetes son declarativos y solo de datos. Un ZIP puede incluir plugin.json y recursos permitidos (PNG, WebP, JPG y JSON). No puede incluir APK, DEX, JAR, bibliotecas .so, clases Java/Kotlin, scripts ni ejecutables. Tori no ejecuta código arbitrario descargado.

Es intencional: descomprimir un ZIP no equivale a ejecutar su contenido. Los puntos de extensión los implementa Tori y cada uno comprueba la capacidad concedida al plugin. Un tipo de extensión solo se considera funcional cuando Tori conecta y prueba su adaptador.

Formato del paquete

my-plugin-1.0.0.zip
├── plugin.json
└── assets/
    ├── icon.png
    └── preview.webp

plugin.json va en la raíz. El identificador debe ser estable y único, y version usa SemVer. Los recursos usan rutas relativas (assets/icon.png); no se admiten rutas absolutas, .., rutas duplicadas ni archivos ejecutables.

Referencia de plugin.json

El manifiesto está en la raíz del ZIP.

CampoTipoObligatorioDescripción
idstringsíID único: minúsculas, números, punto, guion o guion bajo.
namestringsíNombre visible, máx. 80 caracteres.
versionstringsíSemVer, p. ej. 1.2.0.
descriptionstringnoDescripción corta.
authorstringnoAutor o equipo.
typestringnotheme, feature, music_source, widget o utility.
minAppVersionstringnoVersión mínima requerida.
permissionsarraynoCapacidades solicitadas al usuario.
uiobjectnoConfiguración declarativa de interfaz.
musicSourceobjectnoContrato de fuente musical HTTPS.

Capacidades

Son permisos internos de Tori. El instalador muestra la lista y pide aprobación; Tori guarda las capacidades concedidas junto al plugin. Declarar una capacidad no permite invocar APIs Android: Tori implementa y valida cada adaptador, y el usuario puede rechazar la instalación.

CapacidadQué permiteRevisión en la tienda
ui.themeProponer valores de tema.Automática
ui.home_widgetsTarjetas declarativas en Home.Automática
ui.player_overlayComponentes compatibles del reproductor.Automática
ui.embedPersonalizar el aspecto de los embeds de la app.Automática
catalog.music_sourceDeclara una fuente de catálogo musical.Manual
player.queue.readLeer la cola.Manual
player.queue.writeSolicitar cambios de cola.Manual
player.metadata.readLeer metadatos de la pista actual.Manual
network.httpSolicitudes HTTPS mediante un adaptador de Tori.Manual

Las capacidades fuera de ui.* nunca se publican automáticamente en la tienda: pasan siempre por revisión manual.

Ejemplos

Tema + tarjeta Home

{
  "id": "community.neon-night",
  "name": "Neon Night",
  "version": "1.0.0",
  "description": "Paleta oscura con acento violeta para Tori.",
  "author": "Tori Community",
  "type": "theme",
  "minAppVersion": "1.0.0",
  "permissions": ["ui.theme", "ui.home_widgets"],
  "ui": {
    "theme": { "accentColor": "#A78BFA", "backgroundColor": "#09090B", "cornerRadiusDp": 18 },
    "homeCards": [{ "title": "Neon Mix", "subtitle": "Tu acceso personalizado", "icon": "music", "action": "open:search" }]
  }
}

Proveedor de catálogo

{
  "id": "community.example-catalog",
  "name": "Example Music Catalog",
  "version": "1.0.0",
  "description": "Contrato de ejemplo para un catálogo HTTPS.",
  "author": "Example Developer",
  "type": "music_source",
  "minAppVersion": "1.0.0",
  "permissions": ["catalog.music_source", "network.http", "player.metadata.read"],
  "musicSource": {
    "displayName": "Example Catalog",
    "catalogEndpoint": "https://api.example.org/v1/catalog",
    "searchEndpoint": "https://api.example.org/v1/search",
    "artworkBaseUrl": "https://cdn.example.org/artwork/"
  }
}

Un proveedor musical necesita un adaptador de Tori que implemente autenticación, búsqueda, paginación, normalización de metadatos y resolución de reproducción permitida. El manifiesto no crea un reproductor ni elude DRM o controles de acceso. En la tienda, musicSource solo admite URLs HTTPS públicas y requiere catalog.music_source y network.http.

Permisos de Android

Un plugin no puede añadir permisos al AndroidManifest.xml de Tori ni pedirlos directamente: Android los compila en la APK. Si una extensión necesita cámara, ubicación, Bluetooth u otro permiso, primero debe existir un adaptador nativo en una versión oficial de Tori que lo declare y lo solicite. El plugin solo pide la capacidad de Tori correspondiente y el usuario ve el diálogo del sistema cuando proceda.

Cuando una actualización pide capacidades nuevas, Tori muestra el cambio y pide aprobación otra vez. La activación se completa tras cerrar Tori por completo y volver a abrirla; no se borran cachés ni datos.

Instalación manual

  1. Descarga el ZIP desde la web oficial o una fuente HTTPS que consideres confiable.
  2. Abre Ajustes → Tienda de plugins → Instalar desde ZIP.
  3. Tori inspecciona el manifiesto y rechaza rutas peligrosas, ejecutables y paquetes demasiado grandes.
  4. Revisa nombre, versión y capacidades; acepta o cancela.
  5. El paquete se extrae en el almacenamiento privado de Tori (filesDir/tori-plugins/<plugin-id>).
  6. Si se añadieron capacidades nuevas, Tori pide reinicio completo.

Validar el paquete no vuelve confiable a su autor: instala solo plugins revisados. Desde el catálogo, Tori verifica además el SHA-256 de la descarga.

Publicar en la tienda

  1. Entra al portal de desarrolladores con tu cuenta de Pokke (o regístrate).
  2. Acepta los términos y reglas: sin spyware, malware, rastreo no declarado, robo de datos, phishing, suplantación ni piratería.
  3. Sube tu ZIP y un icono (PNG/JPG/WEBP, máx. 512 KB); el id y la version deben coincidir con el plugin.json.
  4. Se ejecuta una verificación automática del paquete y una revisión con dos IAs.
  5. Si pasa todo y solo usa ui.*, se publica. Si hay dudas o pide capacidades sensibles, queda en revisión manual; si es inseguro, se rechaza con los motivos.

Quienes publican reciben el emblema Dev en su perfil de la app. Podemos rechazar, suspender o retirar cualquier plugin.

Límites actuales

  • Máx. 25 MB por ZIP, 8 MB por archivo y 300 entradas.
  • No se ejecutan scripts ni código nativo de terceros.
  • Solo URLs HTTPS para endpoints y descargas.
  • El catálogo muestra solo plugins publicados.
  • En fases posteriores: reseñas completas, actualización automática en segundo plano y adaptadores para cada extensión.

Versiones

Para actualizar un plugin, sube un ZIP con el mismo id y una versión mayor desde el portal. La versión actual sigue publicada mientras la nueva se revisa; si se aprueba pasa a ser la actual, y si pide capacidades que la anterior no tenía, queda en revisión manual.

Las versiones anteriores publicadas siguen disponibles en el catálogo (sección «Versiones anteriores») y en la app. Cada paquete se verifica con su SHA-256. Mientras subes una versión, el portal muestra en tiempo real cada paso de la verificación: integridad, análisis del paquete, las dos IAs y la decisión final.

Personalizar embeds

Con la capacidad ui.embed, un plugin puede cambiar el aspecto de los embeds de la app (no su contenido ni sus enlaces):

"permissions": ["ui.embed"],
"ui": {
  "embed": {
    "accentColor": "#A78BFA",
    "backgroundColor": "#09090B",
    "cornerRadiusDp": 20,
    "layout": "card",
    "showCover": true
  }
}

layout admite card o compact. Como el resto de capacidades, necesita un adaptador en Tori antes de funcionar.
